## 배경

[[03-전체 리소스 태깅 현황]] 에서 찾은 갭을 실제로 메우는 단계
갭은 세 가지

- **서비스 C GPU 루트 모듈** — 태깅 체계 아예 없음
- **공유 인프라·Terraform state 백엔드 루트 모듈** — 서비스명(`Project`) 태그 누락
- **값 불일치 6곳** — provider 기본값과 어긋남

## 접근

공유 인프라 루트 모듈엔 서비스명 대신 "infra"라는 값을 새로 넣기로 결정
여러 서비스가 공유하는 기반 인프라라 특정 서비스로 묶을 수 없었기 때문
Terraform state 백엔드 루트 모듈도 같은 값을 넣으려다가, 이 루트 모듈은 CI의 자동 검증 스크립트가 항상 건너뛰도록 되어 있어서 이번 PR에 넣어도 검증할 방법이 없다는 걸 뒤늦게 확인하고 이번 범위에서 제외
서비스 C의 GPU 루트 모듈은 다른 서비스 루트 모듈들과 같은 패턴으로 태깅 체계를 새로 구성하기로 결정
값 불일치 여섯 군데는 별도 커밋으로 분리해서 처리하기로 결정

---

## 구현

작업을 챕터 단위로 나눠서 진행

1. 공유 인프라 루트 모듈에 `default_tags` 서비스명 값 한 줄 추가 → 관련 provider 세 곳에 자동 전파
2. Terraform state 백엔드 루트 모듈은 검증 불가로 범위에서 제외
3. 서비스 C GPU 루트 모듈에 태깅 정의 파일 신설, provider 세 곳 전부에 `default_tags` 추가
4. 값 불일치 여섯 곳을 provider 기본값에 맞게 정정

여기서부터 예상보다 오래 소요
실제로 CI 파이프라인에 적용해보니 배포 전용 역할에 "태그를 쓰는" 권한 자체가 없는 서비스가 계속 발생
그동안 해당 provider로 태그를 써본 적이 없다 보니 읽기 권한만 있고 쓰기 권한은 부재
apply를 반복하며 막힐 때마다 아래 서비스들의 권한을 순서대로 찾아 추가

- 시크릿 저장소
- 알람
- 컨테이너 이미지 저장소
- 캐시
- 암호화 키
- 데이터베이스
- 로그 저장용 버킷
- 로드밸런서 — 본체/리스너/리스너 규칙까지, 코드 사전 스캔으로 막힐 곳 일괄 정리

작업 중에 곁가지도 몇 개 처리

- **오타 수정** — 배포 전용 역할 권한 설정에 한글 오타 섞여 저장 실패하던 문제 해결
- **드리프트 반영** — 서비스 C 로드밸런서 콘솔 액세스 로그 설정 미반영분 코드에 반영 (미반영 시 apply로 로그 수집 꺼질 뻔함)
- **죽은 코드 정리** — 대체되고 남은 주석 처리 코드 3곳 제거

## 결과

| 대상 | 결과 |
|---|---|
| 서비스 C GPU 루트 모듈 | 리소스 9개 중 6개(컨테이너 서비스 3, 로그그룹 3)에 태그 적용, 나머지 3개는 AWS 쪽에서 해당 리소스 타입이 태그를 지원 안 해서 대상 아님 |
| 값 불일치 6곳 | 전부 정정 후 apply |
| 공유 인프라 루트 모듈 | 리소스 98개에 서비스명 태그 신규 적용 |
| 배포 파이프라인 권한 정책 | 신규 항목 8개 추가 (기존 구문 3개는 액션만 보탬) |

전부 재생성이나 삭제 없이 태그만 바뀐 변경

---

## 회고

지금까지 공유 인프라 루트 모듈이 특정 provider로 태그를 써본 적이 아예 없다 보니, 태그를 처음 붙이는 순간 그동안 안 보이던 권한 공백이 한꺼번에 확인됨
처음엔 에러 나는 대로 하나씩 쫓아가며 고쳤는데, 그러다 보니 apply를 너무 여러 번 반복하게 돼서 나중엔 코드를 먼저 훑어 앞으로 막힐 곳까지 예측하는 쪽으로 방식을 전환
결과적으로 이 방식이 훨씬 효율적

Terraform state 백엔드 루트 모듈은 여전히 남은 과제
별도로 검증 경로를 마련해서 처리할 필요
배포 파이프라인 권한 정책도 이번 일로 계속 땜질식으로 커지고 있다는 걸 확인했으니, 언젠가 한 번은 전체를 정리할 시점 도래 예상
