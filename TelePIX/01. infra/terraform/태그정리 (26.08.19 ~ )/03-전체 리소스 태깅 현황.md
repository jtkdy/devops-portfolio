## 배경

[[01-비용 탐색 태깅 구현]]과 [[02-infra-aws 태그 매핑]]까지 끝내고 나니, 이제 리포 전체가 다 정리됐는지 눈으로 확인하고 싶은 필요성 대두
루트 모듈이 12개나 되다 보니 하나씩 기억으로 판단하기보다 전체를 한 번 더 감사해서 빠진 곳이 없는지 확인하기로 결정

## 접근

`provider.tf`가 있는 디렉토리를 전부 찾아서 루트 모듈 12개를 목록화하고, 각각의 `default_tags` 적용 여부와 실제 쓰인 태그 값을 코드에서 다시 스캔
태그 키뿐 아니라 "지금까지 정한 정책이 정확히 뭐였는지"도 이 참에 코드 기준으로 역산해서 같이 정리하기로 결정

---

## 구현

루트 모듈 12곳을 표로 정리해보니 두 곳이 문제로 확인

| 루트 모듈 | 상태 | 비고 |
|---|---|---|
| Terraform state 백엔드 | 태깅 없음 | 원래부터 대상 아니라고 판단했던 곳, 예상한 결과 |
| 서비스 C GPU 인스턴스 관리 | 태깅 없음 | 전혀 예상 못 한 발견 — 컨테이너 서비스 3개, 로그그룹 3개, 총 9개 리소스가 비용 분해에서 빠져 있었음 |

값 불일치도 다시 발견
provider 기본값은 `Product`인데 리소스에서 개별로 `tags = {...}`를 다시 쓰면서 어긋난 곳이 서비스 D와 C 쪽에서 여섯 군데, 같은 시크릿 저장소 리소스인데 서비스마다 유형 분류(`CostCategory`)가 다르게 매겨진 것도 확인

태그 키 자체도 다시 점검
`Project`/`ReleaseEnv`/`CostCategory` 세 개 말고, 사내 관리 도구 루트 모듈에만 있는 1회성 태그 키 하나와, 비용 분해와 무관하게 콘솔에서 리소스를 사람이 식별하려고 쓰는 `Name` 태그가 리포 전체 38곳에서 별개로 쓰이고 있다는 것도 확인

---

## 결과

| 항목 | 결과 |
|---|---|
| 태깅 체계 없는 루트 모듈 | 2곳 (사내 관리 도구 루트 모듈, 서비스 C GPU 루트 모듈) |
| 값 불일치 | 6곳 |
| 전체 리소스 규모 | 300개 이상 |

이 감사 결과를 그대로 다음 단계인 [[04-태깅 정책 확장 적용]]의 작업 범위로 이관

---

## 회고

서비스 C GPU 루트 모듈은 이번에 안 훑었으면 계속 몰랐을 것으로 추정 — 실제로 과금되는 리소스인데 아무도 눈치 못 챈 채로 넘어갈 뻔함
값 불일치도 마찬가지로, 코드만 보면 다 맞는 것 같아도 리소스 레벨에서 provider 기본값을 덮어쓰는 패턴이 있다는 걸 알고 나서야 확인 가능
앞으로도 태그 작업을 새로 벌일 때마다 이렇게 한 번씩 전체를 다시 스캔하는 습관 필요
