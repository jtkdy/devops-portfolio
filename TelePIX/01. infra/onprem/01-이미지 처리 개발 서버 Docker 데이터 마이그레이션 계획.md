## 배경

이미지 처리 서버(102)의 루트 디스크(`/`) 사용률이 93% 상승 확인
여유 공간 32GB, 이 서버에는 이미지/AI 관련 컨테이너 25개가 돌고 있어서 디스크가 꽉 차면 서비스 전체가 영향받을 수 있는 상황
원인을 뜯어보니 `/var/lib/docker`(이미지, 볼륨, 컨테이너 데이터)가 263GB 차지, 그중 미사용 이미지가 151GB
반면 별도 마운트된 데이터 디스크(`/data`)는 916GB 중 42%만 사용 중이라 여유 충분
Docker 데이터 루트를 `/`에서 `/data`로 옮기는 마이그레이션을 계획

## 접근

미사용 이미지만 정리(`docker system prune`)하는 방법도 검토했지만, 근본적으로 Docker 데이터 자체가 루트 디스크에 있는 구조가 문제라 언젠가 다시 같은 상황이 반복될 것으로 판단
`data-root` 설정을 바꿔서 Docker가 애초에 여유 공간이 넉넉한 디스크를 쓰도록 구조 자체를 바꾸는 쪽으로 방향 설정

작업 방식은 rsync로 데이터를 통째로 복사한 뒤 `daemon.json`의 `data-root`를 새 경로로 바꾸고 Docker를 재시작하는 순서로 결정
이 서버에는 실행 중인 컨테이너가 25개나 있어서(핵심 서비스의 이미지 처리/검색/LLM 관련 컨테이너 다수, 관측성 스택, 벡터DB/캐시, 문서 변환 API 등) 작업 중 전체 서비스가 일시 중단
그래서 팀 공지를 먼저 하고, 작업 전 DB 백업(pg_dump)과 컨테이너 목록 스냅샷까지 남겨두기로 결정
특히 rsync 도중 DB에 쓰기가 발생하면 정합성이 깨질 수 있어서 Docker를 완전히 내린 상태에서 복사하는 방식으로 리스크 제거

## 구현

### 사전 준비

- 팀 공지 완료
- 대상 디스크 여유 공간 확인 (509GB)
- `daemon.json` 백업
- pg_dump 백업 (22GB)
- 실행 중이던 컨테이너 목록 스냅샷 저장

### 작업 절차

1. **최종 확인** — 디스크 여유 공간, Docker 데이터 크기, 전체 컨테이너 상태 재확인
2. **Docker 중지** — `systemctl stop docker docker.socket` (이 시점부터 전체 컨테이너 중단)
3. **rsync 복사** (예상 30~40분) — `rsync -aP /var/lib/docker/ /data/docker/`, 중단되어도 재실행하면 이어서 복사됨
4. **복사 검증** — 원본/복사본 크기, 이미지 수, 볼륨 수 비교
5. **daemon.json 수정** — `data-root`를 새 경로로 변경, 기존 nvidia runtime 설정은 유지
6. **Docker 재시작 및 검증** — `Docker Root Dir` 변경 확인, 이미지 수 일치 확인, 컨테이너 25개 전체 정상 기동 확인
7. **디스크 여유 확인** — 루트 디스크 사용률이 30% 수준으로 떨어졌는지 확인

### 롤백 절차

문제 발생 시 Docker를 중지하고 백업해둔 `daemon.json`을 원복한 뒤 재시작하면 기존 경로(`/var/lib/docker`)로 복귀

### 작업 후 정리

1~2일 모니터링 후 이상이 없으면 원본 경로(`/var/lib/docker`)를 즉시 삭제하지 않고 이름을 바꿔(`.bak`) 하루 이틀 더 보관한 다음 삭제 예정

## 결과 (예상)

| 마운트 | 마이그레이션 전 | 마이그레이션 후 예상 |
|---|---|---|
| 루트 디스크 | 93% | 약 30% (263GB 회수) |
| 데이터 디스크 | 42% | 약 71% (263GB 추가) |

작업은 아직 실행 전이라 실제 결과는 진행 후 이 문서에 업데이트 예정

## 회고 (계획 단계)

작업 자체보다 사전 준비에 더 공을 들임
DB 정합성 문제가 제일 걱정되는 지점이라 pg_dump 백업을 먼저 챙겼고, Docker를 완전히 내린 상태에서만 rsync를 하도록 절차를 짜서 "복사 중 쓰기 발생" 리스크를 아예 구조적으로 제거
원본을 바로 삭제하지 않고 이름만 바꿔서 며칠 더 남겨두기로 한 것도, 재기동 직후엔 안 보이던 문제가 하루이틀 뒤에 나타날 수 있다는 걸 감안한 결정

컨테이너가 25개나 몰려있는 서버라 전체 중단 시간을 얼마나 짧게 가져가느냐가 관건
rsync 복사 자체는 Docker를 내린 채로 30~40분이 걸릴 것으로 예상하고 있어서 이 부분이 실제로 얼마나 걸릴지가 이번 작업의 가장 큰 변수
