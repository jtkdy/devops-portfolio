## 프로젝트 요약

- **왜**: 온프렘은 네트워크 레벨(누가 들어오고 나가는지)과 호스트 레벨(서버 안에서 무슨 일이 있었는지) 탐지 수단이 둘 다 없고, 있는 걸 팀이 보게 만들 리포트 체계도 없음
- **핵심 판단**: 네트워크(Suricata) → 호스트(Wazuh) → 전송 인증(IAM Roles Anywhere) → 리포트(Slack) 순서로 계층을 하나씩 쌓았고, 각 계층에서 나오는 노이즈를 리포트에 얹기 전에 먼저 걸러내는 데 절반 이상의 시간을 씀
- **실행 중 배운 것**: 탐지 체계를 새로 깔면 초반엔 노이즈가 압도적으로 많다는 것(veth promiscuous mode 2,725건/일), 같은 인증 인프라를 여러 서버에 복제하는 과정에서 실수(서비스 중복)가 조용히 반복될 수 있다는 것
- **지금 상태**: 3대 서버 모두 Wazuh Agent Active, High 노이즈 0건 수준으로 정리, 매일 아침 Slack 데일리 리포트에 Wazuh/GuardDuty/CloudTrail이 한 번에 요약 — 다만 S3 데이터 이벤트 로깅 부재는 여전히 남아있는 공백
