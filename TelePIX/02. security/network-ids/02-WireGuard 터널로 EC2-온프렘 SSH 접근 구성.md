## 배경

EC2에서 Ansible로 온프렘 서버 몇 대를 관리해야 하는 상황 발생
가장 단순한 방법은 온프렘 라우터에서 22번 포트를 공인 IP로 열어주는 것이었지만, 그러면 이 서버들에 인터넷 어디서든 SSH 시도가 가능해진다는 뜻
게다가 온프렘 회선의 공인 IP가 고정이 아니라 유동이라, 포트를 열어도 IP가 바뀔 때마다 설정을 다시 잡아야 하는 문제도 있었음

## 접근

포트를 여는 대신 이미 구축돼 있던 [[01-MikroTik 듀얼 WAN 네트워크 아키텍처|WireGuard VPN 인프라]]를 그대로 활용하기로 결정
라우터에 이미 개인 원격접속용 WireGuard 인터페이스가 떠 있었고, 여기에 EC2를 피어로 하나 추가하는 방식이면 새 인프라를 만들 필요 없음

이 방식의 장점은 두 가지

- 22번 포트가 외부에 전혀 노출되지 않는다는 것
- 온프렘 공인 IP가 나중에 바뀌더라도 EC2 쪽 설정(WireGuard 엔드포인트)만 갱신하면 된다는 것

다만 이 방식도 완전한 해법은 아님 — 온프렘 공인 IP는 여전히 WireGuard 자체가 물고 있는 엔드포인트라, IP가 바뀌면 결국 라우터 쪽 endpoint 설정을 갱신해야 하는 수동 작업이 남는다는 점을 미리 인지

## 구현

- EC2(AL2023)에 `wireguard-tools` 설치, 키 페어 생성
- EC2 WireGuard 설정에서 사설 VPN 대역의 고정 주소 할당, 온프렘 라우터를 피어(Endpoint)로 등록, `PersistentKeepalive 25`로 NAT 타임아웃 방지
- MikroTik 라우터에 EC2를 신규 피어로 추가 (허용 주소를 EC2 VPN IP 하나로 제한)
- `systemctl enable wg-quick@wg0`으로 부팅 시 자동 연결
- 연결 확인 후 대상 서버(Docker 컨테이너 서버, 보안 모니터링 서버) 둘 다 ping 정상 확인

## 결과

- EC2 → 온프렘 서버 SSH 경로가 WireGuard 터널을 통해서만 열림, 22번 포트 외부 노출 없음
- 롤백은 EC2에서 터널 내리고 라우터에서 피어 제거하는 두 단계로 간단하게 정리됨

## 회고

VPN 터널로 경로를 감싸는 것과 그 뒤에 있는 서버 자체의 방어선을 갖추는 것은 별개 문제
터널을 통과하면 SSH 접근이 가능해지는 구조인데, 정작 온프렘 서버들의 SSH 자체는 여전히 전체 대역에 열려있었고 한쪽은 방화벽(ufw)이 꺼져 있었음
VPN이 첫 번째 방어선이라면, 그 안에서도 서버별 접근 범위를 한 번 더 좁혀야 완료
