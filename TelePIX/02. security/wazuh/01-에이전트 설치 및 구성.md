## 배경

[[01-MikroTik-Suricata-Wazuh 온프렘 IDS 구축|Suricata로 네트워크 레벨 탐지]]는 갖췄는데, 호스트 레벨은 여전히 보안 모니터링 서버 하나만 커버
Docker 컨테이너 서버와 이미지 처리 서버, 두 대는 온프렘 네트워크에 붙어 있고 팀원들이 상시 작업하는 서버
Wazuh 에이전트를 설치해서 로그인 이상, FIM(파일 무결성 모니터링), 프로세스 감사까지 커버리지 확대 결정

설치 자체는 간단한데, 막상 해보니 두 가지 문제 확인

- **SSH 접근 불가** — 보안 모니터링 서버에서 나머지 서버로 직접 SSH 키 기반 접근이 안 됨
- **syscheck 노이즈** — 설치 후 기본 설정이 개발 서버 환경에 맞지 않아 노이즈가 너무 많음

## 접근

보안 모니터링 서버에 SSH 키가 없어 원격 설치가 불가능
결국 각 서버에 직접 접근해서 수동으로 설치하는 방향으로 결정

설치 후 기본 syscheck 설정을 보니 `/usr/bin`, `/usr/sbin`, `/bin`, `/sbin`, `/boot` 전체를 모니터링 중
개발 서버에서 `apt upgrade`나 `yum update`를 실행하면 수십 개 바이너리가 바뀌면서 매일 대량의 FIM alert가 쏟아지는 구조
모니터링 범위를 `/etc`만으로 축소하는 방향으로 결정

한 가지 중요한 포인트 확인
Manager의 `ossec.conf`와 에이전트의 `ossec.conf`는 완전히 독립적
Manager에서 syscheck 범위를 줄여도 에이전트에는 미적용
각 서버에서 별도로 수정 필요

## 구현

### 환경 정보

| 호스트 | OS | 설치 버전 |
|---|---|---|
| 보안 모니터링 서버 (manager) | Ubuntu 24.04 | Wazuh 4.14.5 (Docker single-node) |
| Docker 컨테이너 서버 | Rocky Linux 9.5 | wazuh-agent-4.14.6-1 |
| 이미지 처리 서버 | Ubuntu 24.04 | wazuh-agent-4.14.6 |

### Manager syscheck 수정

수정 전 백업부터 확보

```bash
cp /opt/wazuh/single-node/config/wazuh_cluster/wazuh_manager.conf \
   /opt/wazuh/single-node/config/wazuh_cluster/wazuh_manager.conf.bak.20260629
```

syscheck 블록에서 디렉토리 범위를 줄이고 ignore 항목 추가

```xml
<!-- 변경 전 -->
<directories>/etc,/usr/bin,/usr/sbin</directories>
<directories>/bin,/sbin,/boot</directories>

<!-- 변경 후 -->
<directories>/etc</directories>
```

```xml
<ignore>/etc/rmt</ignore>
<ignore>/etc/ld.so.cache</ignore>
<ignore>/etc/ca-certificates</ignore>
<ignore type="sregex">.log$|.swp$|.tmp$|.cache$|.pid$</ignore>
```

설정 반영은 컨테이너 재시작으로 적용
볼륨 마운트 구조라 호스트 파일 수정 후 재시작하면 됨

```bash
docker restart single-node-wazuh.manager-1
```

### 에이전트 설치

Rocky Linux(Docker 컨테이너 서버)와 Ubuntu(이미지 처리 서버) 각각 공식 저장소를 추가하고, Manager IP와 에이전트 이름을 환경변수로 지정해서 enrollment까지 한 번에 처리

```bash
# Rocky Linux
rpm --import https://packages.wazuh.com/key/GPG-KEY-WAZUH
WAZUH_MANAGER='<보안 모니터링 서버 IP>' WAZUH_AGENT_NAME='<agent-name>' yum install wazuh-agent -y
systemctl enable --now wazuh-agent

# Ubuntu
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | gpg --dearmor -o /usr/share/keyrings/wazuh.gpg
echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" | \
  tee /etc/apt/sources.list.d/wazuh.list
apt-get update && WAZUH_MANAGER='<보안 모니터링 서버 IP>' WAZUH_AGENT_NAME='<agent-name>' apt-get install wazuh-agent -y
systemctl enable --now wazuh-agent
```

### 에이전트 syscheck 수정 (개발 서버 공통)

에이전트 설치 직후 확인하니 기본값 그대로
Python 스크립트로 정확하게 치환

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 모니터링 디렉토리 | `/etc,/usr/bin,/usr/sbin,/bin,/sbin,/boot` | `/etc` 만 |
| ignore 추가 | - | `/etc/rmt`, `/etc/ld.so.cache`, `/etc/ca-certificates` |
| 파일 타입 ignore 추가 | `.log$\|.swp$` | `.log$\|.swp$\|.tmp$\|.cache$\|.pid$` |
| Docker ignore | 유지 | `/var/lib/containerd`, `/var/lib/docker/overlay2` |

### Agent buffer 튜닝 (이미지 처리 서버, 2026-07-13)

rootcheck 스캔 시작 시 순간적으로 이벤트가 폭주해 버퍼가 꽉 차는 현상 발생
level 9 alert가 데일리 리포트 High 항목에 반복 노출되는 문제

```
rootcheck: Starting rootcheck scan.
wazuh-agentd: Agent buffer at 90%.
wazuh-agentd: Agent buffer is full: Events may be lost.
wazuh-agentd: Agent buffer is under 70%. Working properly again.
```

`events_per_second`를 500에서 250으로 낮춰 Manager로 보내는 속도 감소

```bash
sed -i 's/<events_per_second>500<\/events_per_second>/<events_per_second>250<\/events_per_second>/' \
  /var/ossec/etc/ossec.conf
systemctl restart wazuh-agent
```

alert 억제는 [[03-커스텀 룰 관리]] 참고

## 결과

3대 모두 Active 상태로 확인(보안 모니터링 서버 자체 agent + Docker 컨테이너 서버 + 이미지 처리 서버)
syscheck 수정 후 다음 스캔 주기(12시간)부터 FIM 노이즈 대폭 감소

## 회고

`WAZUH_MANAGER`와 `WAZUH_AGENT_NAME` 환경변수로 설치하면 enrollment까지 자동으로 처리
별도로 agent-auth를 실행할 필요가 없어 설치가 깔끔

보안 모니터링 서버에서 다른 서버로 SSH 키 기반 접근이 안 되다 보니 각 서버에 직접 들어가서 수동으로 진행
Ansible Control Node를 보안 모니터링 서버로 잡고 자동화하면 나중에 서버가 늘어날 때 훨씬 편해질 전망

운영 노드가 추가될 경우 해당 에이전트의 syscheck 설정을 별도로 강화 필요
개발 서버 기준으로 줄여둔 모니터링 범위를 운영 서버에 그대로 적용하면 안 됨
