## aws_signing_helper

| 항목 | 내용 |
|---|---|
| 바이너리 경로 | `/opt/aws_signing_helper` |
| 실행 방식 | serve 모드(systemd) + credential_process(`~/.aws/config`) 병행 |
| serve 포트 | xxxx (내부 커스텀 포트) |
| systemd 서비스 | `aws-signing-helper.service` |
| Docker 프록시 | `aws-signing-helper-proxy.service` (컨테이너 브릿지 IP → 로컬 serve 포트) |

serve 모드를 별도로 띄운 이유는 Docker 컨테이너 안에서 도는 프로세스가 `credential_process` 방식(호스트에서 직접 바이너리 실행)을 쓸 수 없기 때문. 컨테이너는 브릿지 네트워크를 통해 호스트의 serve 포트로 자격증명을 요청하고, 프록시 서비스가 컨테이너 브릿지 IP에서 오는 요청을 로컬 serve 포트로 중계.

```ini
# /etc/systemd/system/aws-signing-helper.service
[Unit]
Description=AWS IAM Roles Anywhere Signing Helper (serve mode)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=keymgr
Group=admgrp
ExecStart=/opt/aws_signing_helper serve \
  --certificate /etc/keymgr/iam-ra/clients/client.pem \
  --private-key /etc/keymgr/iam-ra/clients/client.key \
  --trust-anchor-arn arn:aws:rolesanywhere:ap-northeast-2:<AWS 계정>:trust-anchor/<id> \
  --profile-arn arn:aws:rolesanywhere:ap-northeast-2:<AWS 계정>:profile/<id> \
  --role-arn arn:aws:iam::<AWS 계정>:role/<온프렘 자격증명용 IAM Role> \
  --port xxxx
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`~/.aws/config`(keymgr)도 동일한 인증서로 `credential_process`를 구성해, 호스트에서 직접 CLI를 쓸 때는 serve 모드를 거치지 않고 바로 자격증명 발급. `credential_process` 값은 반드시 한 줄로 작성 필요 — `\` 이어쓰기를 지원하지 않아 멀티라인으로 쓰면 실행 오류.
