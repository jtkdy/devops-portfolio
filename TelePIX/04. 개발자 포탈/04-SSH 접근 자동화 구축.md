## 배경

신규 서버를 포탈 관리 대상으로 편입시키는 작업은 매번 똑같은 수작업의 반복
서버가 하나 늘 때마다 다섯 단계를 손으로 처음부터 다시 진행

- **공용 sudo 그룹 생성**
- **자동화 전용 계정 생성**
- **포탈 공개키 등록**
- **sudo 권한 설정**
- **담당자 개인 계정 생성**

이 반복을 인벤토리 화면에서 버튼 몇 번으로 끝내는 "기본 세팅" 기능으로 자동화하기로 했는데, 만들고 검증하는 과정에서 보안 사고 1건과 자잘한 실행 버그 여러 건을 연달아 경험

## 접근

이 기능은 서버에 미리 짜둔 Ansible 플레이북을 실행하는 기존 자동화와는 성격이 다르다고 판단
플레이북이 돌아가려면 그 전에 접속 계정과 키가 이미 있어야 하는데, 이 기능은 그 "이전" 단계, 즉 서버가 포탈 관리 대상이 되기 위한 부트스트랩이라 플레이북 없이 필요한 명령을 그때그때 조립해서 바로 실행하는 방식으로 설계

여러 차례 리팩터링 끝에 4단계로 정착 (자동화 계정과 포탈 자체의 SSH 접속 계정을 하나로 겸용하기로 하면서 원래 5단계였던 걸 4단계로 통합)

```mermaid
flowchart LR
    A[공용 sudo 그룹 생성] --> B[자동화 계정 생성]
    B --> C[개인 계정 생성]
    C --> D[sudo 권한 부여]
```

EC2는 IAM 역할 기반 SSM으로 이미 자동화되어 있어서 SSH 키 자체가 필요 없기 때문에, 이 기능은 처음부터 온프렘 서버 전용으로 범위 축소

서버 타입별 실행 경로도 같은 원칙으로 분기

- **EC2** — SSM Run Command로 명령 실행, SSH 키를 아예 배포하지 않아도 됨
- **온프렘** — SSH·ansible-playbook 직접 실행, 키가 실제로 서버에 등록돼야 하므로 신뢰 경계가 EC2와 다르다는 걸 전제로 설계

이 분기 로직은 실행 함수 모듈 한 곳에 모아서, 이후 기능이 늘어나도 실행 경로가 여러 파일에 중복 구현되지 않도록 강제
포탈 자체 SSH 프록시(외부 443 → 내부 2222)와 브라우저 기반 웹 터미널도 이 실행 경로를 공유하는 구조로 추가했고, SSM 세션 로그는 S3로 주기 동기화해서 접근 이력 보존

## 구현

만드는 과정에서 실제로 겪은 사고와 버그

- **개인키가 공개키로 오인되어 원격 서버에 등록된 사고**
  - 원인: 포탈 공개키 경로를 개인키 파일명 문자열 치환(`id_ed25519`→`id_ed25519.pub`)으로 추정하던 로직이 Docker 시크릿 마운트 방식 변경으로 무효화 → 개인키 원문이 "공개키"로 반환되어 `authorized_keys`에 그대로 append (겉으로는 "등록 완료"만 표시)
  - 조치: 파일명 추정 대신 개인키에서 공개키 직접 유도(`ssh-keygen -y -f`)로 전환
  - 조치: `ssh-` 접두사 검증 실패 시 빈 문자열 반환하는 이중 안전장치 추가
  - 조치: 영향 서버 전수 점검 후 개인키 블록 제거
  - 조치: `authorized_keys`에 `from=` IP 제한 추가(로테이션은 노출 범위 제한적 판단해 보류)
- **SSH 키 불일치 경고 오탐** — SSH 에이전트의 다중 키 순차 시도(정상 동작) 중 중간 불일치만으로 경고 발송 → 연결 단위 상태 추적으로 최종 인증 실패 시에만 알림 발송하도록 수정
- **PAT 발급 설정의 관리자 권한 미인식** — 토큰 인증 경로가 사용자명만 반환, 권한 정보 부재로 관리자도 일반 사용자로 판정 → 발급 시점 관리자 여부 스냅샷 저장 후 인증 시 재구성하는 방식으로 해결
- **웹 터미널이 표시 이름을 SSH 계정으로 오인** — CLI 경로는 로그인 계정↔서버 계정 매핑 로직 적용, 웹 터미널은 미적용 상태로 남아있다가 표시 방식 변경 시 접속 실패로 드러남 → 웹 터미널도 동일 매핑 적용해 통일
- **셸 명령 실행 버그 5건** — 일괄 발견 및 수정
  - SSH 경유 시 인자 결합 과정에서 특수문자 깨짐
  - 계정명·그룹명 불일치 서버에서 `chown` 실패
  - 실행 이력 저장 함수 인자 시그니처 불일치로 500 에러
  - SSM 실행 결과 다중 라인 병합 미고려로 파싱 오류
  - sudo 권한 없는 디렉토리 탐색 실패로 파일 오판정

## 결과

- **핵심 수치** — 보안 사고 1건 + 실행 버그 8건(셸 명령 버그 5건 포함), 총 9건 발견·수정. 서버 편입 절차 5단계 → 4단계로 축소

지금은 온프렘 서버를 포탈 관리 대상으로 편입시키는 작업이 인벤토리 화면에서 버튼 몇 번으로 종료
개인키 오인 등록 사고 이후로는 키·공개키를 다루는 코드 어디든 "형식이 이상하면 무조건 거부"하는 방어 로직을 기본으로 넣는 게 원칙으로 자리잡았고, 로그인 계정과 실제 서버 계정을 매핑하는 로직도 CLI·웹 터미널 두 경로 모두 하나로 통일

## 회고

크리티컬했던 건 개인키 유출
문자열 치환으로 파일 경로를 추정하는 방식 자체가 "이 환경에서는 항상 이런 규칙일 것"이라는 가정에 기대고 있었고, 그 가정이 깨지는 순간 조용히 잘못된 값을 정상 값처럼 반환
이후로는 값을 추정하기보다 실제로 유도하고, 유도한 결과가 기대한 형식인지 검증하는 코드를 항상 같이 넣는 쪽으로 습관 변화

셸 명령 실행 버그 5건도 결국 하나의 교훈으로 수렴
명령어를 문자열로 조립해서 여러 시스템(SSH, SSM)을 거쳐 전달할 때는 각 시스템이 인자를 어떻게 다시 합치는지, 결과를 어떻게 다시 쪼개는지를 매번 확인해야 한다는 것
로컬에서 잘 되는 명령이 원격 실행 경로를 한 번 더 거치면 얼마든지 다르게 해석될 수 있다는 걸 여러 번 재확인
